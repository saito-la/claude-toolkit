# メールアドレス台帳の運用

作成日：2026-07-25　改訂日：2026-08-04

## 概要

全プロジェクト共通。メール検索で確認済みの「氏名 ↔ メールアドレス」の対応を、**プロジェクトごとに保存し、次回の検索機会で即座に再利用できる**ようにする仕組み。取り違え防止（表記揺れ・同姓同名・引用スニペット誤ヒット）と検索の高速化が目的。

正本の置き場所は原則プロジェクトの `CLAUDE.md`。件数が育つ／既存名簿がある場合のみ CSV に逃がす。解決手順は [[GMAIL-MCP]]（メール検索の原則）に組み込む。

## 背景・動機

- メール検索は必ずアドレスで絞り込む（`from:`/`to:`/`cc:`）。人名キーワードは取り違えるため使わない
- しかしアドレスをその都度 `From:` を開いて確定する作業は、確定結果がセッションを越えて残らないと毎回繰り返しになる
- 確定済みアドレスをプロジェクト単位で蓄積しておけば、次回は「まず台帳を見る」だけで済む

## CLAUDE.md 直書きを既定にする理由

`CLAUDE.md` はタスクに関係なく毎セッション自動でコンテキストに載る。CSV は「メール作業のセッション」で grep したときだけ載る。この違いから損得が決まる。

- **検索時コストが実質ゼロ**：既にコンテキスト内にあるので grep も tool call も不要。「そのアドレスは知っている」状態になる
- **上流の継承**：コンテナ（複数のサブプロジェクトを束ねるディレクトリ）の `CLAUDE.md` はサブプロジェクト作業時にも読まれる。共有連絡先をコンテナ側に置けば全サブプロジェクトへ自動伝播する
- 小さく安定した連絡先（〜10件程度）ではこの2点が CSV の grep 往復を上回る

代償は「メール作業をしないセッションでも常時コンテキストを消費する」こと。10件なら小さい（〜数百トークン）が永続的なので、育つ場合は CSV に逃がす（下記）。

## 規約

### 1. 既定：プロジェクトの CLAUDE.md に台帳を持つ

`CLAUDE.md` に固定見出し **`## メールアドレス台帳`** を置き、**表ではなく箇条書き**で列挙する（表はメンテが煩雑・変換で崩れるため）。

```markdown
## メールアドレス台帳

このプロジェクトのメール検索で確認済みのアドレス。検索は必ずここを起点にする。
新規に From: で確定したら即時ここへ追記する。

- `tanaka@example.co.jp` — 田中一郎（例社・渉外）2026-07-25確認
- `suzuki@foo.ac.jp` — 鈴木花子（Foo大）2026-07-20確認
```

- 1行1アドレス。形式は `` `メールアドレス` `` — 氏名（所属・役割）確認日
- 共有したい連絡先はコンテナ側 `CLAUDE.md` に置き、サブプロジェクトへ継承させる
- 氏名の漢字・読みは推測して書かない。台帳は氏名の正本ではなく索引なので、確定できない読みは書かず所属等の識別情報で足りればよい

### 2. 例外：CSV に逃がす条件

次のいずれかに当てはまるときは `CLAUDE.md` ではなく `_reference/email_addresses.csv` に置く。

- **既存の名簿 CSV がその相手をカバーしている**（組織の職員名簿など）→ そちらが一次情報源。台帳に二重に書かない。台帳は「名簿外＝外部関係者」だけを扱う
- **件数が 20 件級に育つ／育つ見込み**（常時コンテキスト課税が無視できなくなる）
- **スクリプトで扱いたい**（重複排除・ソート・監査）

CSV の列：`email, name_kanji, name_romaji, org_role, confirmed_date, source`。1行1アドレス、一意キーは `email`。

### 3. 更新タイミング：その場で即時追記

アドレス未確認の相手は「キーワード検索 → ヒットしたメールの `From:` を開いてアドレス確定 → 台帳へ即時追記 → 以降そのアドレスで検索」。確定した**直後**に追記する（セッション末にまとめない。取りこぼし防止）。

### 4. 解決順序

メール検索でアドレスを引くときの順序。

1. プロジェクト `CLAUDE.md` の `## メールアドレス台帳`（既にコンテキスト内。コスト0）
2. 既存の名簿 CSV（組織の職員名簿があればそれ）・`_reference/email_addresses.csv`
3. 個人の知識ベースに人物ページがあればその別名欄
4. 無ければキーワード検索 → `From:` 確定 → **台帳へ即時追記**（1／2の基準で置き場所を選ぶ）

## 定期見直し

台帳は放置すると膨らむ。月次程度で次を点検し、育ちすぎた台帳は CSV へ移す。

- 各 `CLAUDE.md` の `## メールアドレス台帳` のエントリ数（20 件以上なら CSV へ）
- 同一アドレスが複数プロジェクトに散在していないか（コンテナ側へ集約できる）

点検は提案までにとどめ、自動改変はしない。
