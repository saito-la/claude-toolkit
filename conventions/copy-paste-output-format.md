# コピペ前提テキストの出力規約

作成日：2026-07-05
改訂日：2026-10-14

## 概要

全プロジェクト共通。メール文案・チャット文面・URL・コマンド等「そのまま貼り付ける前提」のテキストを Claude が出力するときの作法。

## 規約

### URLは単独行に置く

メール・文書中のURLは括弧・カッコで囲まない。末尾の `)` がURLの一部と誤認されるため、前後を改行してURLのみの行にする。

### コピペ前提のテキストは `.txt` + `open` かクリップボードで渡す

メール文案・チャット文面・URL・コマンド等「そのまま貼り付ける前提」の文字列はチャット内コードブロックで出力しない。

- (a) 一時ディレクトリに `.txt` を書き出して開く（macOS は `open <path>`、Windows は `Invoke-Item <path>`）
- (b) クリップボードに入れる（下の「クリップボードへの入れ方」に従う）

チャット文面（Google Chat・Slack・LINE・Teams 等へ投稿する文）は (b) だけで渡し、応答本文には表示しない。本文には宛先と要点だけを書く。文面を本文に出すと、読み手は同じ内容を画面と貼り付け先の2か所で読むことになり、修正の指示も画面の版に対して出てずれる（2026-10-14 の指示）。

機微情報（個人情報等）を含む場合はファイルを残さずクリップボード優先。複数ある場合は1件ずつ、ユーザーが「次」と言ったら次を入れる。PowerShell コマンドの `!` 付き実行依頼は、選択を問わず自動的に (b) を使う。

### クリップボードへの入れ方

**入れ方は OS で違う。ここに書いた方法だけを使う。**

macOS —

```bash
printf '%s' '...' | pbcopy
pbcopy < <file>
```

Windows — PowerShell の `Set-Clipboard` を使い、ファイルは UTF-8 と明示して読む。

```powershell
Set-Clipboard -Value ([System.IO.File]::ReadAllText($path, [System.Text.UTF8Encoding]::new($false)))
```

**Windows で `clip` を使わない。** `pbcopy` が無いからと Git Bash から `clip < <file>` に読み替えると、UTF-8 のバイト列がコンソールのコードページ（日本語環境では cp932）として解釈され、**非 ASCII 文字がすべて化ける**（2026-08-02、`NMC-RINKEN15` で発生）。`Set-Clipboard` は .NET の文字列として渡すのでこの変換が挟まらない。

投入後は読み戻して一致を確認する（`Get-Clipboard -Raw` の文字数と元テキストの文字数を比べる。大小文字を区別する `-ceq` で照合する）。日本語を含むテキストでは毎回確認する。

### クリップボードに入れた内容は本文にも省略せずそのまま書く

チャット文面は対象外で、本文に表示しない（上の節）。上書きされたら Claude に入れ直しを頼む。

クリップボードに入れた文字列を案内するとき、本文側を `/rename ...`・`git commit -m "..."` のように `...` で省略しない。**完全な文字列をそのまま書く**（短いものは文中に、長いものは本文中に1件だけ提示する）。

理由＝**クリップボードは揮発性**で、ユーザーが貼り付ける前に他のコピー操作で上書きされ得る。上書きされた時点で、本文が省略形だと**何を貼るべきだったか復元できない**（Claude に聞き直す往復が発生する）。本文に全文があれば、そこから拾い直せる。

機微情報を含む場合はこの規約より前段の「ファイルを残さずクリップボード優先」を優先し、本文には全文を書かず要旨で示す。
