# 採番の起点

作成日：2026-09-13
改訂日：2026-09-13

## 規則

全プロジェクト共通。人が読むために付ける番号は1から始める。0番を作らない。

対象は、工程・区間・段階・フェーズ・ステップ・章・節・分類・版・優先度など、文書と設計の中で順序や区別を示すために自分で付ける番号すべて。前段・準備・開始前にあたるものも例外にせず、それを1番とし、以降を1つずつ繰り下げる。

## 対象外

- プログラムの内部。配列の添字、ループカウンタ、行番号・列番号のオフセット、API が返す値。言語と処理系が0起点を定めているものは、そのまま0起点で書く。
- 外部の規格・仕様・システムが番号を定めているもの。CDISC の変数値、法令の条項、学会の様式番号、取引先の採番など、こちらが決めたのではない番号は原典どおりに写す。0番があってもそれを1へ直さない。
- 量を表す0。件数0、指摘0件、未決0はここでいう採番ではない。

## 理由

0番は「本番の前」「実施しなくてもよい準備」と読まれる。実際には人が判断を決め切る最も重い段をそこへ置くことがあり、番号の与える印象と中身が食い違う。

n番目と番号がずれる。区間0から始めると区間3は4番目になり、会話・口頭・議事録で「3番目の区間」と「区間3」が別のものを指す。指し違えたことに気づく手がかりが無い。

0起点は、前段を後から足したときの一時しのぎとして生まれることが多い。1つ繰り下げる手間を避けた結果が、その後ずっと残る。

## 既存の番号の移行

一括置換はしない。その文書を編集する機会に合わせて移行する（日付表記の規約と同じ運用）。

移行する前に、番号がどこまで入り込んでいるかを数える。本文だけなら安い。ファイル名・ディレクトリ名・見出しアンカー・識別子・CSV の列と値・スクリプトの条件分岐・他リポジトリの参照に入っていれば、置換の範囲がコードと外部へ広がるので、移行するかどうかをその場で決める。数えずに置換を始めない。

置換は大きい番号から順に行う。小さい番号から繰り上げると、繰り上げた結果を次の置換が拾って二重にずれる。

移行を見送った文書が残っている間は、新旧の番号が併存する。どちらの体系で言っているかを書き添える。

## 章番号

見出しに振る番号の書式は次のとおり。区切りと末尾がピリオド、番号と見出し文字列の間は半角スペース1つ。

```
1. 見出し1
1.1. 見出し2
1.1.1. 見出し3
2. 見出し1
2.1. 見出し2
```

Google Docs 用の章番号ツール（https://github.com/nnh/chapter_numbering）と同じ書式である。md と Google Docs で番号の見え方を揃え、md から docx・Google Docs へ変換したときに番号を振り直さずに済ませるための一致である。

md では文書題名を `#` 1つで持つので、`##` を第1レベルとして番号を振り、題名には振らない。

実装は `~/.claude/scripts/number-headings.py`。既にある番号は剥がして付け直すので何度でも実行でき、コードブロックの中は見出しとみなさない。見出しの階層が飛んでいる文書（`##` の直下に `####` があるなど）は番号に 0 が出るため、書き込まずに該当行を報告して止まる。直すのは階層であって番号ではない。

```bash
python3 ~/.claude/scripts/number-headings.py <file.md> [--top-level 2] [--dry-run] [--remove]
```

## 章番号を振る文書・振らない文書

判断の軸は1つ。その文書の節を、文書の外から名指しする必要があるか。

振る。手順書・規程・仕様書・設計文書。レビュー指摘で「7.3 の出口条件」と書く、メールで節を指す、PDF や Google Docs で配る、版が変わっても節の同一性を追う、といった用途が実際にあるもの。紙と PDF ではスクロールもアンカーも使えないため、番号が節の唯一の住所になる。見出しが概ね15個を超える文書、2階層以上ある文書はたいていここに入る。

振らない。生きた文書（`overview.md`・`issues.md`・`action-items.md`）、README と索引、見出しが数個の短い md、時系列が住所になっている記録（作業ログ・欠陥の記録・通過記録）。

振らない理由は、生きた文書と記録で共通している。節が頻繁に増減するため番号が動き、外から指した参照が黙って腐る。番号は節の住所である以上、住所が動く文書には向かない。README と索引は、それ自体が入口であって節を名指しされる側ではない。

節を足すと後続の番号が全部動く。これは番号を振る文書が負う費用であり、振らない文書に振らない理由でもある。番号を振った文書を編集したら、節の増減があったかにかかわらずスクリプトを通し直す。
