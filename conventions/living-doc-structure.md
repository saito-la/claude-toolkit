# 生きた文書の構成規約

作成日：2026-06-19　改訂日：2026-08-01

## 概要

全プロジェクト共通。`overview.md` のような案件の中核ドキュメント（＝随時更新される「生きた文書」）は、いつ読んでも一読で最新の全体像が掴める**最終形だけ**を保つ。修正履歴・確認日・暫定ステータスを本文や見出しに溜めない。

## 背景・動機

- 「（補足・2026-06-19 確認）」「（たたき台）」のような確認履歴・暫定マークが見出しや本文に混ざると、最新状態の把握が遅れ、誤読の原因になる
- ISO文書管理の発想で「最終形＝単一の真実」を重視し、冗長・履歴混在を避ける
- 既存の作法（説明資料の見出しは名詞句のみ／next action は別ファイル）を、進行中案件の生き文書にも一貫適用する

## 規約

### 適用対象

- 随時更新する中核ドキュメント：`overview.md`、`issues.md` 等
- 個人ナレッジベース（llm-wiki 等）の entity・synthesis ページ（随時追記される点で同じ性質。経緯は `log.md` 側が担う）
- 単発の使い捨てメモ、git log から状態が自明なコードベースは対象外

### 見出し

- **名詞句のみ**。括弧書きの副題・確認日・ヘッジ語（「たたき台」「補足」「メール時系列」「〜版」等）を見出しに付けない
- 例：「## 収支サマリ（一次資料より・2026-06-19確認）」→「## 収支」、「## 適格／対象外の切り分け（たたき台）」→「## 適格と対象外」
- 本文中の各項目も同様：「（2026-07-16◯◯確認）」のような確認履歴の逐一の付記は避け、確認済みの事実として端的に書く

### 章番号・連番

- 章・節・ステップ・フェーズ（Phase）等の**連番は「1」から始める。「0」を使わない**（`## 0.`／`Step 0`／`Phase 0`／`第0章` 等は禁止）。見出しだけでなく本文・図・表の中の連番にも適用する
- 前置き・導入・前提は番号を振らず、「概要」「背景」等の**名詞見出し**にするか本文に置く
- Claude Code の PostToolUse フックで 0 始まりの章番号を自動検出させる運用も可能

### 更新日

- 文書冒頭の本文に「随時更新（YYYY-MM-DD 時点）」の1行だけ置く。見出しや各節に日付を散らさない
- **`action-items.md` はこの表記の対象外**。`最終更新: YYYY-MM-DD` を使う（正本は [[20260531-action-items-convention]]「更新日表記」）。生き文書は最終形を保ち続ける文書、`action-items.md` は消化されて減っていく台帳であり、更新の意味が違う

### 履歴・凍結記録の分離

- **next action・未解決事項は `action-items.md`** に分離（→ [[20260531-action-items-convention]]）。生き文書側には「未確認事項と次アクションは action-items を参照」と1行だけ残す
- point-in-time の凍結記録（議事録・調査スナップショット・過去版）は `snapshots/` か日付プレフィックスの別ファイルへ
- 方針・計画の記録は日付プレフィックスの別ファイル（`YYYYMMDD_plan_*.md` 等）に保存し、生き文書からは参照のみ
- **訂正履歴を本文に残さない**：`~~旧記載~~ → 訂正後` のような取り消し線・Before/After形式を本文中に溜めない。訂正したら本文は最終形（正しい内容）だけにする。経緯を残す必要があれば文書末尾の別セクション（例：「更新履歴」）か、`log.md` 等の別文書に置き、本文はどの時点で読んでも現在の正しい状態だけが読める状態を保つ

### 推奨構成

案件フォルダは次の構成を標準とする。

```
<case>/
  overview.md        # 全体像（生き文書・最終形のみ）
  issues.md          # 未解決の論点（生き文書）
  action-items.md    # 現況・未確認事項・次アクション
  roadmap.md         # 工程と律速（該当時）
  snapshots/         # 議事録・調査・過去版の凍結記録
  attachments/       # バイナリ原本（gitignore）
```

## CLAUDE.md への参照追加

グローバル `~/.claude/CLAUDE.md` の「指示の原則」に、本規約へのポインタを1行追加し全プロジェクトに適用する。
