# スプレッドシート構造の原則

作成日：2026-07-12　改訂日：2026-08-01

## 概要

全プロジェクト共通。Google スプレッドシート（および表計算全般）を設計するときは、**入力層と表示層を分離**し、**入力層はクエリ可能なテーブル（正規化 tidy table）**として作る。データは入力→表示の一方向にのみ流す。壊れにくく、再利用（QUERY / VLOOKUP / IMPORTRANGE）でき、「どれが正か」が一意に定まる状態を保つ。

## 背景・動機

- 入力・計算・体裁を1シートに混ぜると、行の並べ替え・書式変更で数式が壊れ、正本が曖昧になる
- 「見た目のための構造」（セル結合・空行・色分けで意味づけ）はクエリ・集計・IMPORTRANGE を破壊する
- ISO 文書管理の発想で「単一の真実（正本）」を重視し、二重入力・履歴混在を避ける

## 規約

### ① 入力層と表示層を分け、データは一方向に流す

- 表示層（閲覧・印刷・集計）の値は数式（QUERY / VLOOKUP / IMPORTRANGE / ARRAYFORMULA）で導出する。**表示層では手入力しない**
- データの流れは常に 入力層 → 表示層 の一方向。表示層を編集して入力層に戻す運用を作らない

### ② 入力層は「クエリ可能なテーブル」＝正規化 tidy table にする

- **1テーブル＝1エンティティ／1行＝1レコード／1列＝1属性**
- 1行目にヘッダ。各列は型を統一（日付列に文字列を混ぜない等）
- **一意キー列を持つ**（結合・参照のアンカー。例：メールアドレス・ID）
- 禁止：セル結合／空行・空列で区切る／セルの色・書式で意味を持たせる／1セルに複数値を詰める（複数値は別テーブルに正規化するか区切り文字で1列に統一）

### ③ 体裁・同じ事実の扱い

- 表示・印刷の体裁（結合セル・書式・レイアウト・見出し装飾）は**表示層だけ**に置く
- **同じ事実を複数ファイルに二重入力しない**。他ファイルの正本はキーで参照（IMPORTRANGE + VLOOKUP）して派生表示する

### ④ 自由文・備考列を置かない

- **「備考」等の自由文列を作らない。** 自由文はゴミ溜め化し、集計・検索・再利用を壊す。値は**カテゴリ化できる列**に落とす（選択肢は Master シートで管理）
- 自由文の説明・文脈・但し書き・手順は、スプレッドシートでなく**文書（md／Google Docs）側で管理**する。スプレッドシートは構造化データ、文書は説明、と役割を分ける
- 台帳に書きたくなった但し書きは、多くが別文書（手順書・方針）に正本がある。**重複させず参照**する

### ⑤ 1行目は見出し行として固定・中央・太字

- **各シートの1行目は見出し行**とし、全シート共通で **ウィンドウ枠を1行固定（frozen row = 1）・太字・中央揃え** にする
- データシートの1行目は列ヘッダ、Usage シートの1行目は目次の見出し（下記）

### Usage目次シートの書式

複数タブを持つスプレッドシートには先頭に Usage シートを置き、次の書式で各タブを説明する。

- **1行目は見出し行**：A1「シート名」／B1「使い方」等（⑤に従い固定・中央・太字）
- **A列2行目以降はシート名のみ**を記載する（1タブ＝1行）
- **シート名の一行下から、そのシートの内容に関する説明をB列**に書く（複数行可）
- **タブとタブの間には空行**を挟む
- **スプレッドシート全体に係る事項は Usage シートのB列**に記載する（Usage 行のB列）

### 分割の軸

「誰が入力するか」「どこに保存するか」はいずれも**権限境界の代理変数**。一般則として次で決める。

- **ファイル分割は権限境界で決める**：*編集してよい人* または *見てよい人* が違えば別ファイルにする（Google の共有はファイル単位のため）。別ファイルは保存場所（共有ドライブ／フォルダ）も権限境界に合わせて分ける
- **タブ分割は機能で決める**：同一権限の中で「入力テーブル／ビュー」を分ける

> 系：同じ人（同一権限）が入力するデータは入力シートを1つにまとめる。別の権限の者が入力するデータは、別ファイルにして置き場も分ける。

### 実装上の注意

- `IMPORTRANGE` / `QUERY` は **Google Sheet 同士（Google Drive 内）**でしか動かない。Box 等に置いたファイルは live 参照できない。ライブ連携するマスターとビューは共に Google Drive（共有ドライブ）に置く。Box 等は**エクスポート・スナップショット（PDF/CSV）の保管**に使う
- `IMPORTRANGE` の初回参照は**手動承認（アクセスを許可）が1回必要**。API では自動化できない
- 結合は**キーの VLOOKUP／QUERY** で行い、行順（位置）に依存させない
