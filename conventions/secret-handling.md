# 秘匿情報の取り扱い

作成日：2026-08-11
改訂日：2026-08-11

APIキー・アクセストークン・パスワード・秘密鍵を扱うときの規約。対象は Claude の出力
（応答本文・コマンドの標準出力）と、リポジトリに置くファイルの両方。

## 値を画面に出さない

**秘匿値そのものを標準出力・応答本文に出してはいけない。** 出した瞬間にセッションの記録へ
平文で残り、あとから消せない。同一性の確認・設定漏れの検査は、値を出さずに次のどれかで行う。

```bash
# 指紋（値を復元できない）
printf '%s' "$KEY" | shasum -a 256 | cut -c1-8

# 設定されているかだけ
[ -n "$KEY" ] && echo "設定あり" || echo "未設定"

# 長さだけ
echo "${#KEY}"
```

**シェルの既定値展開を「マスク」に使わない。** `${VAR:-未設定}` は**変数が設定されていれば
値そのものを出す**。設定の有無を出したいときに書き間違えやすく、実際にこれで API キー3本を
セッションログへ出してしまった（2026-08-11）。有無を出すなら `[ -n "$VAR" ]` で分岐する。

外部コマンドの出力に秘匿値が混ざりうる場合は、パイプで伏せ字にしてから読む。

```bash
some-command | sed 's/\(AQ\.\|AIza\|sk-\|ghp_\)[A-Za-z0-9_.-]\{6,\}/<REDACTED>/g'
```

## リポジトリに値を置かない

**追跡ファイルに秘匿値を書かない。** private リポジトリでも同じ——**git 履歴からは消せない**
（消すには `filter-repo` と force push が必要で、clone 済みの全端末が pull できなくなる）。

実体は git の外（`~/.config/<tool>/*.env` 等、権限 600）に置き、追跡ファイル側は
その読み込みだけを書く。**値を持つ場所は常に1箇所にする**——2箇所あるとズレて、
「更新したのに反映されない」という原因の分かりにくい失敗になる。

端末間で運ぶ必要があるものは、そのための経路（例: `bootstrap-new-mac.sh --pack`）に載せる。
チャット・メール・スクリーンショットで送らない。

## 露出させたときの扱い

秘匿値を記録に残してしまったら、**気づいた時点で報告する。** 黙って伏せ字に直すだけでは、
値が有効なまま残っていることが利用者に伝わらない。報告に含めるもの。

- どこへ出たか（セッションログ・コミット・ファイル）
- そのキーに何ができるか（課金が紐づくか、読み取り専用か、対象アカウント）
- 失効・再発行するかの判断材料（課金が紐づくキーは金銭被害があるため優先度が高い）

判断は利用者が行う。伏せ字化・保管場所の移動を済ませても、**再発行しない限り値は有効**である
ことを明示する。
