# セッションの回収

落ちたセッションの JSONL を読める Markdown に書き出し、新しいセッションで作業を続けられるようにする。以下 `$SKILL` はこの SKILL.md が置かれているディレクトリの絶対パス。symlink 経由で読み込まれていても実体のディレクトリを解決して使う。

## 症状と判断

画面に出るのは次の3点だけである。

- 応答が `API Error: No response from API` の1行だけ
- 待ち時間が毎回ほぼ同じ（6〜7分）
- 「続けて」を何度打っても同じ結果になり、会話が1手も進まない

JSONL 上は `error: "server_error"`・`model: "<synthetic>"`・`isApiErrorMessage: true` で記録される。API から中身のある返答が一切返っておらず、ローカルの会話ファイルは壊れていない。入力が15万トークンを超えた大きな会話で起きやすい。

「続けて」はそれまでの会話全体を付けて同じ大きさの要求を送り直すので、同じ条件で落ちる。`/compact` も会話全体を1回の要求として送るため、同じく落ちうる。したがって落ちたセッションは直そうとせず、中身を回収して新しいセッションへ乗り換える。落ちたセッションは `--resume` しない。

## 手順

### 1. 落ちたセッションの JSONL を特定する

セッションは `~/.claude/projects/<作業ディレクトリのパスの区切りをハイフンにした名前>/<セッションID>.jsonl` にある（例：`/Users/me/Projects/foo` なら `-Users-me-Projects-foo`、Windows の `C:\Users\me\Projects\foo` なら `C--Users-me-Projects-foo`）。

回収を頼まれたこのセッション自身も同じフォルダに書かれているので、更新時刻が最も新しい1本は自分自身である。API Error の記録を持つものから選ぶ。

```bash
d=~/.claude/projects/<ディレクトリ>
ls -lt "$d"/*.jsonl | head -5
grep -l '"isApiErrorMessage":true' "$d"/*.jsonl
```

候補が複数あれば、更新時刻と、ユーザーが覚えている作業の内容で確かめてから進める。

### 2. Markdown に書き出す

```bash
python3 $SKILL/scripts/rescue-session.py "$d/<セッションID>.jsonl" \
  -o <書き出し先>/session-<セッションIDの先頭8桁>-transcript.md \
  --user-label <ユーザーの呼び名>
```

- Windows で `python3` が動かなければ `python` か `py` で呼ぶ
- ツールの実行結果は既定で 4000 文字で切る。`--full` で全文、`--limit N` で上限を変える
- `--user-label` はユーザー発話の見出しに出す名前で、既定は「ユーザー」

書き出し先は、作業していたプロジェクトの git に入れない置き場（`.gitignore` 済みの `attachments/<日付>/` など）にする。会話の生の記録で、人物や未公開の検討がそのまま残るため、コミットしない。

### 3. スクラッチパッドを退避する

そのセッションのスクラッチパッドに残っている中間生成物を、プロジェクトの置き場へ移す。セッションを捨てると回収できなくなる。場所は Mac なら `/private/tmp/claude-<uid>/<ディレクトリ>/<セッションID>/scratchpad`、Windows なら `%LOCALAPPDATA%\Temp\claude\<ディレクトリ>\<セッションID>\scratchpad`。

### 4. 生きた文書に書く

回収した事実と未了の作業を、プロジェクトの生きた文書（`overview.md`・`action-items.md` 等）に書く。書き出した Markdown そのものを次のセッションに読ませるのではなく、判断に要る事実を文書へ移す。

### 5. 新しいセッションで続ける

新しいセッションを起こし、手順4の文書と退避した素材だけを読ませて続ける。

## 回収できないもの

思考（thinking）の中身は JSONL に保存されない。回収できるのは指示・報告文・ツール呼び出しとその結果までで、モデルが頭の中で組み立てた判断は残らない。判断まで届いていた作業は、素材を渡して組み直す。

## 予防

- 大きな文書を読んだら、その場で要点を md に落とす。会話の中だけに置かない
- 入力が15万トークンに近づいたら、区切りのよいところで成果物を書き出し、`/clear` して新しいセッションに移る
- 一次資料は必ずファイルとして残す。会話が飛んでも取り直しが要らなくなる
- 締め切りのある作業を1本の長いセッションで抱えない
