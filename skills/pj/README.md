# pj の設計

作成日：2026-11-04

使い方（`/pj` の判定・起動・訂正の手順）は同じフォルダの [SKILL.md](SKILL.md) が正本。この文書は仕組みと、そう作った理由を持つ。

## 1. 構成

### 1.1. スクリプト

- `scripts/pj-go.sh`：`/pj` の高速パス。索引の更新、判定、DIRECT なら即起動までを1回で行う
- `scripts/pj-open.sh`：起動の部品。Orca が動いていれば `pj-orca.sh` へ渡し、無ければ新しい窓（Mac は osascript で iTerm2、Windows は Windows Terminal）を開いて `claude` を起動する
- `scripts/pj-orca.sh`：Orca の作業場で起動する。新規、`claude --resume` での再開（`--resume`）、動いている端末を前に出す（`--focus`）の3つ
- `scripts/pj-platform.sh`：Mac と Windows の差をまとめた部品。ほかの bash のスクリプトが読み込む（9章）
- `scripts/pj-worktree.sh`：新しい窓で開くときに、本体が埋まっていれば worktree へ振り替える。空のまま残った worktree を回収する
- `scripts/wt-finish.sh`：worktree（pj のもの・Orca の作業場）の成果を既定ブランチへ統合し、片付ける
- `scripts/wt-cleanup-later.sh`：Windows で、worktree の中の claude が終わってから片付ける（9章）
- `scripts/pj-router.py`：判定の本体（`route`）と、開いた先へ渡す依頼文を作る `request`
- `scripts/pj-recommend.py`：索引・カタログ・プロジェクト一覧の単一情報源（`index`・`catalog`・`list`・`--suggest-frontmatter`）
- `scripts/pj-ngram.py`：文字N-gram の類似度。単体でも叩ける
- `scripts/pj-learn.py`：選んだ文の記録（`record`・`forget`・`list`）

### 1.2. 置き場

- `~/.cache/pj/index.json`：索引。`CLAUDE.md` 群から自動で作り直すので直接編集しない
- `~/.local/state/pj/learned.<端末名>.jsonl`：選んだ文の記録。再生成できないのでキャッシュとは別に置く。環境変数 `PJ_STATE_DIR` で変えられる

## 2. 判定の流れ

### 2.1. 2つの層

```
① 決定的語彙一致 ─── 完全一致（パス／末尾のフォルダ名）／別名／パス部分一致
      │ 当たらなければ
      ▼
② 全件のカタログを類似度順に並べて渡す ─── 判断は呼び出し側（/pj の Claude）
```

①は「登録済みの語がクエリ文にそのまま含まれるか」しか見ないので、日本語の長文はほぼ必ず空振りして②に落ちる。②の並び順は文字N-gram の類似度で決める。並べ替えを入れる前は全件をパス順に並べるだけで、実質「自分で探す」状態だった。件数は絞らない。上位が外れても呼び出し側が下位から拾い直せるようにするため。

結果は3つのどれかになる。

- DIRECT：①で1つに絞れた。確認なしで開く。誤起動の危険はこの確信の範囲に限られる
- CANDIDATES：①で複数、または弱い一致だけだった
- CATALOG：①が空振りした。全件の圧縮カタログ（約4kトークン）を返し、会話の文脈を持つ Claude が選ぶ

### 2.2. 試し方

```bash
python3 scripts/pj-router.py route "文言"     # 判定だけを見る
python3 scripts/pj-ngram.py "文言"            # 類似度の上位10件
```

### 2.3. 簡素化の経緯

2026-07-26 に4層を2層にした。撤去したのは、選択の履歴での即決（旧 L0）、未実装だったローカル埋め込み（旧 L2）、haiku に推薦させる層（旧 L3）である。履歴で即決していた文はすべてプロジェクト名やパスの断片で、①が履歴なしで同じ結果を出せた。履歴は `CLAUDE.md` の欠落も隠していた（索引に無いのに履歴だけで開けていたフォルダがあった）。haiku の層は、会話の文脈を持つ呼び出し側の Claude の方が的確に判断できるので外した。

## 3. CLAUDE.md の書き方

### 3.1. 索引に入るもの

`~/Projects` の下（深さ5まで）で `CLAUDE.md` を持つフォルダが候補になる。`.pjignore` を置いたフォルダは外れる（テンプレートの配布物など、作業を起こす場所でないもの）。索引に入るのは次の4つ。

- 見出しに目的の語（`pj-recommend.py` の `PURPOSE_HEADS`）を含む節の本文（無ければ最初の節）
- 見出しに切り分けの語（`pj-recommend.py` の `BOUNDARY_HEADS`）を含む節の本文
- `<!-- pj-tags: ... -->`
- 先頭の frontmatter

### 3.2. frontmatter

```yaml
---
org: <最上位のフォルダ名など>
unit: [所管部門]
domain: [分野タグ]
aliases: [別名, 略称, よく使う言い回し]
lifecycle: standing     # standing|time-boxed|archived
status: active          # active|dormant|done
confidential: false
related: [紛らわしい近傍プロジェクトの relpath]
---
```

- `aliases` が一番強い。書いた語がクエリ文にそのまま含まれていれば、競合が無い限り DIRECT で開く
- `domain` は弱い信号。短い一般語は長文に偶然出やすいので、候補止まりにしている
- `unit` はルーティングに使わない。改組のときにフォルダを動かさず値を書き換えるための欄で、同じ部門名が多くのフォルダに重複して弁別力が無い。索引には載るがカタログには出さない

別名の案は `python3 scripts/pj-recommend.py --suggest-frontmatter <パスの一部>` で出せる。サブフォルダ名・ファイル名から未登録の語を拾うだけで、書き込みはしない。

### 3.3. 近傍の切り分け

似た言葉が複数のプロジェクトに関係する場合、正しい側に `aliases` を足すだけでは取り違えは防げない。紛らわしい側の `CLAUDE.md` に「この話題の正本は `<正しいプロジェクト>`」と書く。索引はこれを切り分けとして拾い、CANDIDATES の理由とカタログに出す。見出しの語（3.1）が入っていない節に書いても拾われない。

## 4. Orca で開く

- `pj-open.sh` は、Orca に届くか（`orca status`）を確かめてから `pj-orca.sh` を呼ぶ。届かない、または作業場を作れなかったときは iTerm2 で開く。環境変数 `PJ_LAUNCHER=iterm` を置くと Orca を使わない
- 作業場は毎回新しく作る（名前は `<フォルダ名>-<月日-時分秒>`）。本体が空いていれば本体で開く `pj-worktree.sh` の振り替えは使わない。終えるときは `wt-finish.sh` が統合して作業場を消す
- リポジトリの最上位なら Orca のエージェント起動（`orca worktree create --agent`）を使う。下位フォルダなら、作業場を作ってから端末で `cd <下位フォルダ> && claude` を実行し、そこの `CLAUDE.md` を最初から読ませる。Orca のエージェント起動は作業場の最上位でしか始められないため
- 作業場の基点は、ローカルの既定ブランチと origin のどちらが他方を含むかで選ぶ。Orca の既定は origin（作る前に Orca が fetch する）で、ローカルにしか無いコミット（push 前、または同期が止まって push できないもの）が作業場に入らない。判定はローカルの参照だけで行い、fetch はしない（`pj-worktree.sh` と同じく速度のため）
  - ローカルが進んでいるだけなら、ローカルを基点にする（`--base-branch`）。何も失わない
  - ローカルが遅れているだけなら、origin を基点にする。何も失わない
  - 分岐していれば origin を基点にする。ローカルを基点にすると、origin だけにあるコミットが見えないうえ、終えるとき `wt-finish.sh` がローカルだけのコミットを全部載せ替えて push し、同期を止めている衝突をその作業場で解くことになる。代わりに、開く下位フォルダの中だけに触れるローカルのコミットを cherry-pick で載せる（origin に同じ変更があるものは除く）。1件でも外に触れていれば載せない。本体があとで `pull --rebase` すると、同じ変更として落ちる
- 下位フォルダが作業場に入らない（未コミット、origin で移動・削除された、載せるべきコミットが外にも触れる）ときは、作業場を作らずに理由を出して止め、終了コード 3 を返す。`pj-open.sh` も iTerm2 へ戻らずに止まる。戻ると Orca の一覧に載らない窓が別の基点で開き、止まったことに気づきにくい。どの基点で開いたかは起動の報告の末尾に括弧で出る
- Orca に登録していないリポジトリは、その場で登録する
- 直近セッションの継続（`pj-open.sh -c`）は Orca に同じ場所で再開する手段が無いので、iTerm2 で開く

## 5. 依頼文の受け渡し

- 打った文に用件があれば、開いた先への最初の指示として渡す。行き先の名前だけなら渡さない。判定は `pj-router.py request` で、行き先のパスの各段と別名、「作業」「開いて」などの語と助詞を除いて4文字未満なら名前だけとみなす
- 渡す依頼の末尾には「（振り分け：「<原文>」から <relpath> を選んで開いた。…）」の1行が付く。開いた先のセッションは、どの文で選ばれたかが分かるので、行き先が違えばその場で開き直しと学習の付け替えができる
- `--prompt-file` の文は、シェルや AppleScript の文字列に埋め込まず、起動するシェルが読む。日本語と引用符の崩れを避けるため

## 6. 学習

### 6.1. 憶え方

②で人や Claude が選んだとき、その文を記録し、以後そのプロジェクトの照合テキストに混ぜる。次に似た言い回しで打つと②の類似度が上がる。キーワードを抽出も生成もせず、文をそのまま憶える。2文字ずつ刻む照合が語形の揺れを吸収するので、言い当てられる語を人が選ばずに済む。

①が当てた文（DIRECT）は憶えない。順位が変わらないうえ、よく使うプロジェクトの照合テキストだけが太って何にでも当たるようになる。同じ理由で1プロジェクトあたり直近10件で頭打ちにする。4文字未満の文も憶えない。

旧 L0 と違い、即決には使わない。順位に効くだけで、DIRECT を作るのは①だけなので、誤って憶えても誤起動には直結しない。候補は索引からしか出ないので、`CLAUDE.md` の欠落も隠さない。

### 6.2. 端末間の共有

端末ごとにファイルを分け（`learned.<端末名>.jsonl`）、各端末は自分のファイルだけを書く。1ファイルを共有すると、毎回全体を書き直す作りのため同期ツールで必ず「両側で変更」になる。読み出しは全ファイルの併合で、`(q, path)` で重複を除いて新しいものを採り、併合後にも10件の頭打ちを効かせる。`forget` は他の端末のファイルにある記録も消す。

複数の端末で共有するときは、git の外で同期される置き場を `PJ_STATE_DIR` に指す。git には載せない。クエリ文に人名・案件名が残るためで、扱いは会話ログ（`~/.claude/projects/`）と同じ平文のローカルデータとして見る。

## 7. 作らないもの

- 該当プロジェクトが無いときの自動新規作成、プロジェクトの分割・統合の提案。必要になった時点で設計する方が安い
- ローカル埋め込みによる意味検索。文字N-gram で代えた。埋め込みはモデルという別の維持対象を増やし、起動のたびにロードが要る。N-gram は依存が無く、100件程度で0.1ミリ秒で済む
- ①で複数が当たったとき「より長い別名に包含される側を外して即決する」規則。2026-10-15 に試作したが、既存の別名と学習済みの文のうち約50件の判定が意図せず変わった。短い別名の側が正しいことも多く、包含関係は意図の強さを示さない。両方が当たるときは CANDIDATES に留め、文脈の判断と切り分けの節に任せる

## 8. 困ったときは

- 何を憶えているか：`python3 scripts/pj-learn.py list`
- 誤って憶えた：`python3 scripts/pj-learn.py forget "文言" <relpath>`
- 新しい `CLAUDE.md` を作ったのに出てこない：`python3 scripts/pj-recommend.py index --rebuild`
- 出てこないプロジェクトがある：そのフォルダに `CLAUDE.md` が無い。作業拠点なら足し、作業拠点でないなら `.pjignore` を置いて意図して外す

## 9. Windows

### 9.1. 対応の範囲

- Git Bash の上で、Mac と同じスクリプトを動かす。差は `scripts/pj-platform.sh` が吸収し、Mac の動きは変えない。2026-11-04 に `311C4W991` で、索引・判定・Windows Terminal と Orca での起動・worktree の振り替えと回収・片付けを確かめた
- 要るのは Git for Windows（Git Bash・`cygpath`）、Python 3、PowerShell（pwsh、無ければ Windows PowerShell）、Windows Terminal。Orca は `tools/orca/README.md`「2.3. Windows」で入れる
- 直近セッションの継続（`-c`）と pj リンクは、まだ Windows で試していない

### 9.2. 違う作り

- 窓：Windows Terminal の新しい窓で、起動用の `.ps1` を PowerShell に実行させる。Orca の作業場でも、端末で同じ `.ps1` を実行する（Orca のエージェント起動は使わない）。依頼文と作業フォルダはコマンドの文字列にも引数にも埋め込まず、`.ps1` がファイルから読む。Git Bash からネイティブの exe へ渡す引数は、非 ASCII が崩れることがあるため
- 受け継いだ変数：`.ps1` は、今のセッションから受け継いだ `CLAUDE_*`・`AI_AGENT` を外してから claude を起動する。Windows の窓と Orca は起動元の環境を受け継ぐので、Claude Code の中から開くと `CLAUDE_CODE_CHILD_SESSION` が残り、開いた先が子のセッション扱いになって記録を残さない（2026-11-04 に「Transcript saving is off」で確認）。利用者やマシンの環境変数に置いた `CLAUDE_*` は外さない
- 稼働中のセッション：Git Bash の `ps` は MSYS のプロセスしか見えず、`lsof` も無い。Claude Code が稼働中のセッションを作業フォルダごと書く `~/.claude/sessions/<pid>.json` を読み、`tasklist` でまだ動いている pid に絞る
- パスの形：git は `C:/…`、`$HOME` は `/c/…` を返すので、比べる前に `cygpath` で揃える。Python の標準出力は既定で cp932・CRLF になり、bash が日本語と行末を読み違えるので、UTF-8・LF に揃える
- 片付け：動いているプロセスの作業フォルダは消せない。`wt-finish.sh` は統合と push までを行い、worktree とブランチの片付けは `wt-cleanup-later.sh` を切り離して起動して任せる。それは worktree の中の claude がすべて終わるのを待ち（最長24時間）、未コミットも origin に無いコミットも無いことを確かめ直してから消す。Orca の作業場は Orca に消させ（端末のシェルも止まる）、1回目で消えなければ間を置いてやり直す。記録は `~/.cache/pj/wt-cleanup.log`
