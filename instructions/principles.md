## 指示の原則

- **同じ事実を2箇所に書かない（単一正本＋参照）**：記述・データ・手順が重複すればいずれズレる。**ズレの検証という将来の作業を発生させないために、正本を1つ決めて他は参照させる。** 実行可能なもの（スクリプト・設定ファイル・一次データ）が事実を持つなら、それを正本とし文書へ写さない。既存の重複を見つけたら指摘し、統合を提案する。コード・文書・設定・スプレッドシート・memory のすべてに適用する
- 作業前に対象ファイル・ディレクトリ構成を確認し、変更前に現状と差分を明示する
- 複数マシンで再現できるよう、手順はコマンドで示す
- 破壊的操作（削除・上書き）の前には必ず確認を求める
- **一次データを最優先する**：人物・件数・状態など具体的事実を主張する前に、必ず最新の一次データ（エクスポート・スプレッドシート・APIレスポンス等）の該当行を直接確認する。CLAUDE.md・memory等の二次情報源は古い前提で現データと突合する
- **新規スクリプト・ツールを作る前、および特定ツールの利用可否を判断する前に、既存を確認する**：`~/.claude/skills/` を検索してから判断・提案・実装する。**`ToolSearch` は MCP ツールしか検索できない**——Bash 経由の CLI・グローバル npm パッケージは ToolSearch に出ないが存在し得る。「ToolSearch で見つからない＝存在しない」と即断しない
- 文書中で文字修飾を使わない：太字（`**`）・斜体・下線・ハイライトを本文に入れない。強調は語順・見出し・箇条書きの構造で示す。理由＝修飾は読み手の判断を先取りする書き手の主観であり、多用すると強調が均質化して意味を失う。Word・Google Docs 変換時の体裁崩れの一因にもなる。コード・パス・識別子・列名の `` ` `` は修飾ではなく種別の表示なので使ってよい。適用先は成果物の md に限らず、ユーザーへのチャット応答も含む。この項目自体が実例として修飾なしで書かれている（ただし本ファイル等の既存のグローバル指示は、LLM への指示強度として太字が機能しているため一括変更しない）
- **文書作成時は表（テーブル）を避ける**：明らかに表形式が好ましい場合を除き、箇条書き・見出し・散文で表現する。理由＝メンテナンスが煩雑で、Google Docs／Word 変換時に崩れやすい。データそのものを扱うスプレッドシートは対象外
- **md 見出しは名詞句のみ**：括弧書き・副題・確認日・「（案）」「暫定」等のヘッジを入れない
- **節を持つ章の直下に本文を置かない**：`### 7.1` `### 7.2` のような節がある章では、`## 7.` の直下に本文・箇条書き・表・コードを書かない。章の直下に書きたい内容があるなら、それを最初の節（`### 7.1`）にする。理由＝章直下の本文と節の本文が同じ重さに見え、目次にも現れないため、読み手が全体の構造を把握できない。見出し階層のどの水準にも適用し、スクリプトで md を生成する場合も同じ（生成側を直す）
- **文書の日付は本文冒頭の2行**（表記の正本。全 md 共通で、生きた文書・`action-items.md`・手順書で使い分けない）。見出しや各節に日付を散らさず、日付の後ろに改訂回数や反映内容を括弧書きで足さない（何が変わったかは本文と git log が持つ）。既存文書の一括置換はせず、その文書を編集する機会に合わせて移行する

  ```
  作成日：YYYY-MM-DD
  改訂日：YYYY-MM-DD
  ```
- **外貨建ての金額には必ず円換算を括弧書きで併記する**：ドル・ユーロ・ポンド等を書くときは、概算でよいので `USD 968.83（約15万円）`・`年766.8万ドル（約12億円）` のように括弧で円を添える。本文・箇条書き・スライド・チャット応答のいずれにも適用する。理由＝読み手は外貨の桁を即座に把握できず、円が無いと金額の比較と妥当性の判断ができない。**正とするのは原典の外貨額で、円は桁感の補助**であり、換算値で原典の値を書き換えない。丸めの粒度は桁が伝わる範囲でよい（億円単位なら整数、万円単位なら有効2〜3桁）。レートは文書内で統一し、**同じ数字を扱う既存文書があればそのレートに揃える**（揃えないと同じ原典から違う円額が出て、どちらが正しいかの検証作業が発生する）。レートの出所を明示できるとよい（例＝日銀の基準・裁定外国為替相場）
- **md に URL を書くときはクリック可能な形式にする**：`[ラベル](URL)` を基本とし、URL の文字列そのものを見せたいときは `<URL>` で囲む（angle bracket autolink）。裸の URL をそのまま本文に置かない。理由＝ビューアによっては裸の URL がリンクにならず、Word・Google Docs へ変換したときにも落ちる。一覧・台帳のように URL 自体が情報のときは `<URL>`、文章中で参照するときは `[ラベル](URL)` を使う。**スクリプトで md を生成する場合も同じ**（生成側を直す）
- 「openして」「開いて」はBashで `open <path>` を実行する（Readでの内容表示ではない）
- shellコマンドは `!` での実行を案内せずBashツールで直接実行する（ブラウザログイン等インタラクティブ認証が必須な時のみ依頼）

## 作業種別ごとの規約

`~/.claude/conventions/` が正本。**着手前に該当ファイルを読む。**

- コピペ前提のテキスト（メール文案・チャット文面・URL・コマンド等） → `copy-paste-output-format.md`
- 生きた文書（`overview.md` 等）・md 見出し規約の詳細 → `living-doc-structure.md`
- 工程・区間・段階・章などの採番（1から始める・0番を作らない） → `numbering-starts-at-one.md`
- スプレッドシート設計 → `spreadsheet-structure.md`
- 手順書・マニュアル → `sop-manual-authoring.md`
- ファイル・フォルダの命名／整理 → `file-naming-and-folder-hygiene.md`
- 案件（出張・イベント・治験等）の情報をどのフォルダに置くか → `case-record-single-location.md`
- 積み残し（next action）の管理 → `action-items-convention.md`
- セッション終了時のテンポラリファイル整理 → `session-end-auto-file-move.md`
- APIキー・トークン・パスワードの扱い（画面に出さない・追跡ファイルに置かない） → `secret-handling.md`

`~/.claude/conventions/` には各自が追加した規約も入る。上の一覧に無いファイルがあれば、それも同じ扱いで読む。
