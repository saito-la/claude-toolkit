## Box ファイルへのアクセス

Box URL（`*.app.box.com/file/<ID>`）が提示されたら **WebFetch は使わず Box CLI（`box files:get` / `box files:download`）を使う**。WebFetch は OAuth2 認証を通れずログインページにリダイレクトされて失敗する。docx 等はダウンロード後に `pandoc -t markdown` で読む。

## 探索コマンドの実行証拠

**探索を `timeout` で包まない。** macOS 標準に `timeout` は無い（GNU coreutils を入れれば `timeout`・`gtimeout` の両方が入るが、brew を使えない端末があり、あることを前提にできない）。`timeout 30 grep -ril ... 2>/dev/null` と書くとコマンドは実行されないまま空の出力を返し、`2>/dev/null` が `command not found` を捨てるため、**0件のヒットと区別が付かない**。実際にこれで「記載なし」と誤報告した（2026-08-16）。時間制限が要るなら Bash ツールの `timeout` パラメータを使う。

**探索コマンド名がシェル側の定義に食われることがある。** `log show ...` は zsh の `log` 定義に食われて `too many arguments` で落ちた。`2>/dev/null | grep | tail` に埋もれたため、0件ヒットと区別が付かなかった。`timeout` は不在、`log` は別物が居るという違いだけで、結果は同じである。対処は `/usr/bin/log` のようにフルパスで打つこと。

**探索の走査範囲が足りていないことを0件と読まない。** `find <dir> -maxdepth 3 -name 'ar*'` で「残骸ファイルは無い」と報告したが、実際の所在は深さ4で、ファイルは存在していた。`-maxdepth`・`-name` のパターン・除外オプションはいずれも、コマンドが正常に実行されたまま結果を空にする。**「実行されたか」の証拠だけでは足りず、「探した範囲が対象を含むか」も併せて確かめる。**

**「無い」「ヒットしない」と報告する前に、その検索が実行された肯定的証拠を取る。** 終了コード、`grep -c` の件数、走査対象のファイル数など。ラッパーの不在は本体の不在と違い、コマンドの意味を変えずに実行そのものを消すため、空の出力は0件の証拠にならない。**そして「無い」と言う前に、対象が在る場所を1件は肯定的に確認する**（探索対象を含むディレクトリの実在、既知のヒットが取れること）。

## リポジトリの現在地

**リポジトリが最新か・遅れているかを述べる前に `git fetch` する。** `git status -sb`・`git log origin/<branch>`・`git rev-list HEAD..origin/<branch>` はいずれも、**最後に fetch した時点の remote-tracking ref** と比べている。実際には遅れていても `behind 0` と表示され、しかもその表示は現在の状態を測ったように見える。上の探索の節と同じ型の誤りで、コマンドは正常に実行されたまま答えだけが古い。

2026-09-12 に実際に踏んだ。fetch せずに `## master...origin/master` を読んで「上流と同じ位置」と報告したが、fetch すると 44 コミット遅れていた。**さらに悪いことに、その古い木を根拠に「依存ファイルが存在しない」と判断し、実在する2件を無いものとして扱った。** 遅れた木の上で行った調査・実装・判断はすべて巻き添えになる。

したがって次の順序を守る。

- **その木の上で何かを調べる・書く前に fetch する。** 判断の後に fetch しても、判断はやり直しになる
- clone を開いた時点で fetch されている保証は無い。セッション開始時の自動 pull は作業ディレクトリのリポジトリにしか効かず、セッション途中で触り始めた別のリポジトリには及ばない。長いセッションでは開始時に取った状態も古くなる
- **遅れていた場合、そのリポジトリで書いたものは基点が古い。** そのまま push せず、最新へ追随してから書き直すか、差分が影響しないことを確かめる
- 未 push のコミット（`ahead`）も同じ理由で fetch 後に見る。古い基点の上に積まれていることがある

## シェルスクリプトの生成

**Bash ツールに渡すコマンド文字列では、バックスラッシュが1つに潰れることがある。** ヒアドキュメントを `<<'EOF'` でクォートしていても起きる。`tr -d '"\\'` と書いたものが `tr -d '"\'` としてファイルに落ち、`tr: warning: an unescaped backslash at end of string is not portable` を出しながら意図と違う動作をした（2026-08-30）。**同じセッションで、それを直そうとした Python の置換文字列でも同じことが起き、`str.replace` が2回続けて空振りした。**

**バックスラッシュを含む引用をスクリプトに書かない。** 除外する文字を列挙する代わりに、残す文字を列挙する（`tr -d` ではなく `tr -cd 'A-Za-z0-9._-'`）。改行を含む書式は、書式そのものに入れず後段の `echo` で足す。どうしても要るなら Python 側で `chr(92)` として組み立てる。

**Git Bash からネイティブの exe へ非 ASCII を引数で渡すと壊れる。** `curl.exe` へ `-d` で日本語と絵文字を含む JSON を渡したところ、ANSI コードページを経て化けたまま送信された（2026-08-30、Google Chat の Webhook が返す本文のバイト列で確認）。**スクリプトのファイル自体は正しい UTF-8 のままなので、`cat -A` でファイルを見ても異常が見つからない**——壊れるのは引数として渡す瞬間だけで、しかも送信は成功して HTTP 200 が返る。**非 ASCII をネイティブ exe へ渡すときは、引数ではなくファイルに書いて渡す**（`curl` なら `--data-binary "@$tmpf"`）。同じ理由で、`python -c` に日本語を書いたコードもツール経由で壊れる。**Python へ渡すコードは `.py` に書き出してから実行し、標準入力を読むときは `sys.stdin.buffer` で生バイトを受ける**（`PYTHONIOENCODING=utf-8` を併用する）。

**この壊れは `bash -n` を通る。** 構文としては正しいまま意味だけが変わるため、構文検査では見つからない。**書いた直後に `cat -A` か Python の `repr()` でファイルの実バイトを確かめる**——特に `tr`・`sed`・`grep` の引用と、正規表現を含む行。

## 作業完了の Chat 通知

「終わったら通知して」「終わったら教えて」、または単に「notify」「通知して」と言われたら、次を実行して有効にする。**既定では通知は出ない**ので、言われたときだけ付ける。言われていないのに有効にしない。

**仕組みそのものの話をしているときの `notify` は対象外。** `notify-chat-arm.sh` を直す、通知の設計を相談する、といった文脈で出てくる語では有効にしない。有効にするのは、これから走らせる作業の終わりを知らせてほしいと頼まれたときだけ。

```bash
~/.claude/hooks/notify-chat-arm.sh once <<'EOF'
<何を頼まれたかを1行で>
EOF
```

`once` は次の1回だけ、`session` はそのセッションのあいだ毎回、`--off` は取り消し。**要約は標準入力から渡す**——引数に非 ASCII を載せると壊れる（上の「シェルスクリプトの生成」）。フックがまだ入っていない端末ではスクリプトが見つからず、Webhook を設定していない端末ではその旨を返すだけで、どちらも何も起きない。その場合は通知できないことを伝えて作業を続ける。

**要約に書いてよいのは、通知先スペースの相手に見せてよいことだけ。** 人事・評価・被験者・未公開の検討に触れる作業では、要約を空にするか「依頼の作業」程度に留める。一度スペースへ出たものは取り消せない。

通知が実際に出るのは、処理が全部終わって静かになってからの1回だけで、キューに依頼が積まれている間は出ない。仕組みの正本は `akiko-office` の `setup/claude-hooks/README.md`。

## GAS / clasp

GAS・clasp・Apps Script への言及時、または `gas/` ディレクトリ操作時は `~/.claude/GAS-CLASP.md` を読むこと（Spreadsheet 書き込み方針を含む）。

## SAS

SAS・`.sas` ファイル・SAS ログへの言及時、`.sas` を読み書きするとき、または実行の可否を問われたときは `~/.claude/SAS.md` を読むこと（文字符号化・バッチ起動・成否判定・他言語との突合を含む）。SAS に macOS ネイティブ版は無いが、リモート実行の経路が張ってあることがあるため、`which sas` が空なことを根拠に「使えない」と答えない。

## Google Sheets 関数

Google Sheets の数式（QUERY・ARRAYFORMULA・LAMBDA等）作成・デバッグ時は、既知の落とし穴があれば自分の環境ドキュメント（無ければ適宜作成）を確認する。新しい落とし穴・パターンを解決したら追記して蓄積する。

## Google Calendar イベント作成

gcal-* MCP で `location` を設定するときは裸のURLのみを入れる。「Zoom: URL」等のラベルを前置するとGoogle Calendar上でクリックできなくなる。

## モデル使用方針

既定は **Opus 5**（`settings.json` の `"model": "opus"`）。大量ファイルの機械的な一括処理や、レート制限を抑えたいと言われたときは **Sonnet 5** への切り替えを提案してよい（切り替えは `/model` でユーザーが手動で行う）。

## セッション終了

「セッションを終わります」「終えます」「終了します」等の発言を検知したら `~/.claude/SESSION-END.md` を読んで実行すること。
