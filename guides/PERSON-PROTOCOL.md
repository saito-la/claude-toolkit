# 人物情報プロトコル

本プロトコルの呼称は PERSON-PROTOCOL。人物（**本人を含む全員**）の固有情報を扱うときの厳守ルールで、SessionStart で本ファイルが提示される。詳細は `~/.claude/LLM-WIKI.md`。R3・R4 の実行手順の正本は `~/.claude/SESSION-END.md` Step 4。

**`~/.claude/PERSON-PROTOCOL-local.md` があれば併せて読む**（無ければスキップ）。個人・組織に固有の名簿正本の所在はそちらにある。

## R1 参照優先
人物の **肩書・役割・所属・メール・関係性・経歴** を主張する前に、正規ローカル記録を**必ず読む**：
- その他の人物・本人の詳細 → `~/llm-wiki/wiki/entities/<slug>.md`。
- **「主張」には発言・行動・関係の帰属を含む（全プロジェクト強制）。** 会議録の話者同定（ダイアライゼーション）・議事録・面談メモで「誰が言ったか」「誰と誰が知り合いか（人脈・接点）」を割り当てる前に、**登場する各人物の entity を先に読んでから帰属を確定する**（実例 2026-07-10：ある医師の発言を entity 未読のまま別人に帰属させ、話者を取り違えた）。
- ⚠️ **global CLAUDE.md「私について」は概要であり正本ではない**。本人の正確・最新の肩書は自分の wiki entity ページを正本とする。
- **組織・チームのメンバーの基礎情報（氏名・漢字・読み・ローマ字・所属・職位・メール）は、その組織の名簿正本（member master）を一次参照とする（全プロジェクト共通）。** entity・memory・CLAUDE.md 等の二次記述で上書きしない（二次記述の読み・ローマ字は過去の推測であり得る）。**読み・ローマ字も名簿正本の該当列で確認する。** 名簿正本が無い場合は R2-K のフォールバックに従う（カタカナ等で保留し、漢字・確定読みに昇格しない）。

## R2 推測禁止
人名（漢字含む）・役職を推測しない。未確認の固有名はカタカナ等で保留し、確認が取れるまで正式文書に書かない。

**読み（ふりがな）も推測しない。漢字が読めても読みは推測扱い**とし、researchmap／KAKEN（無ければ J-GLOBAL／所属公式ページ）に**明記された値だけ**を採用する。無ければ「読み不明」として漢字のみで留め、“よくある読み”を当てない（実例 2026-07-11：名の「岳」を出典未確認のまま「たけし」と推測したが、researchmap の登録値は「がく」だった）。読み・経歴・学位・所属・年が不確かな場合も、同じ登録値を準一次ソースとして正とし、生成AIの要約より優先する。確定できない読み・年は書かない。

**R2-W 新規 entity は登録前に確認する（2026-07-23 決定）：** wiki に人物 entity を新規作成するときは、**その場で上記ソースを引いて読み・漢字・ローマ字を確認してから登録する**。「読み未確認」での確定登録を既定にしない（確認を試みても取れない場合に限り保留表記を残す）。確定値は summary/aliases に入れ、`sources` に URL を残す。

**R2-K 漢字は逐字コピーのみ・slug/romaji から逆生成しない（最重要・全プロジェクト強制）：**
人物の漢字氏名を**チャット・文書・コード**のいずれにも書く前に、**その人物の `entity` ページ（または組織の名簿正本）を当該セッションで実際に開き、aliases/タイトルの漢字をそのまま転記する**。
- **slug・ローマ字・かな・読み・メールアドレスの綴りは「鍵」であって氏名・読みのソースではない。** slug や romaji から漢字を生成するのは**捏造**（romaji→漢字は一意でない。例: "Hiromasa" に対応する漢字表記は複数あり、よく見る表記が登録値だとは限らない。実際に頻度の高い方を当てて誤った）。
- **entity を開いていない人物の漢字は書かない。** slug を別の人物の entity 本文で見ただけでは不可——必ず本人の entity を開く。開けない/存在しない場合は slug・romaji・カタカナのまま記載し、漢字に昇格しない。
- かな表記の名（例「かおり」のように名がかなで登録されている人物）を漢字化しない。記録がかなならかなで書く。

**R2-S 漢字の出所リスト（2026-07-27 決定。「漢字で書いてあるソース」を無差別にコピー元にしたことによる当て字の再発防止）：**
R2-K の「逐字コピー」が許されるのは**次の一次ソースを当該セッションで実際に開いた場合だけ**。漢字が書いてあるからといって、出所を問わずコピー元にしてはならない。

- **一次（コピー可）**：本人が書いた署名（メール末尾・名刺・文書の署名欄）／Google Contacts の登録値（Name・Notes）／組織の名簿正本（member master。所在は R1 を参照）／researchmap・KAKEN・所属公式ページの登録値／**上記のいずれかを `sources:` に明記した** entity。
- **漢字ソースにしない（禁止）**：
  - **音声文字起こし（ASR）の出力**。ASR は音声から漢字を推定する装置であり、人名は当て字になる（実例：ASR が「ハマノ」と読まれる姓を実際の登録漢字と異なる字で出力した）。引用の形でも人名漢字を持ち出さない。
  - OCR・LLM の生成物・要約・議事録の下書き。
  - **プロジェクトの md・memory・CLAUDE.md 等の二次記述で、出所が併記されていないもの**。「唯一の情報源だから正しい」とみなさない。
  - **`sources: []`（出典が空）の entity の aliases**。R2-W 導入（2026-07-23）以前に作られた entity には未検証のものがある。
  - slug・ローマ字・かな・メールアドレスの綴り（R2-K 本文のとおり）。
- **未確認時の書き方**：姓が一次で取れていれば「姓＋さん／先生」に留め、名は書かない。姓も未確認ならローマ字・カタカナのまま。**フルネーム漢字は一次を引いてから初めて書く。**
- **人名漢字を文書に新規に書くときは、同時に出所を残す**（entity の `sources:` に入れる、または本文に「（Contacts 確認 2026-07-27）」等）。出所を書けないなら、その漢字はまだ書いてはいけない。

**実例（2026-07-27 に発覚。3週間気づかれなかった）：** 2026-07-04 のセッションで会議の関係者一覧を作った際、逐語記録には姓しか出ていない3名について、同じ表に並べていたメールアドレス（`<名>.<姓>@` 形式）のローマ字から名の漢字を逆生成して記載した。3名とも当て字で、登録漢字は別字だった。これらが二次記述として残り、3週間後のセッションで検証されないまま会議グロッサリへ再利用され拡散した。**当て字は書いた瞬間より、後から二次記述として再利用されるときに被害が広がる。**

## R3 セッション末の追記
関与・言及した各人物の新事実（役割変更・接触記録・評価・訂正）を該当 entity と `~/llm-wiki/log.md` に**漏れなく**追記する。

## R4 wikiへの集約とsensitivityラベル
人事評価・機微情報も含め人物情報は**すべて wiki entity に記載**し、frontmatter `sensitivity:`（public / internal / confidential、人物は既定 confidential）で管理する。別の機密ストアに分離しない（単一情報源＝wiki）。

## R5 客観的事実の記録先
2026-07-30 決定。person-research 等の fan-out 調査で収集した客観的事実（論文全件・研究費全件・招待講演・受賞歴・同姓同名の切り分け根拠等）は、**`sources/handoffs/<日付>-people-research/<slug>-research-dossier.md` に件数・数値・固有名詞・時期を間引かずに格納する**（代表数件への要約禁止）。`wiki/entities/<slug>.md` 側は現所属・関係性・研究テーマ・接触記録を3〜5行程度の要約に留め、詳細は dossier への参照リンクのみを置く。R1 の日常的な参照（肩書・所属・関係性の確認）は entity だけで完結する密度を保つこと。
