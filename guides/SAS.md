# SAS

作成日：2026-08-22
改訂日：2026-08-22

SAS を扱うときの共通の作法。`~/.claude/SAS-local.md` があれば併せて読む（無ければスキップ）。どの端末からどう実行するか、ログがどこに出るかはそちらにある。

## 実行できるかを推測で答えない

SAS に macOS ネイティブ版は無い。したがって Mac で `which sas` が空なのは当たり前で、それは「この環境で SAS を実行できない」ことの証明にならない。リモート実行の経路が張ってあることがある。

可否を答える前に次の順で調べる。ローカルだけ見て「使えません」と答えない。

1. `~/.claude/SAS-local.md` を読む
2. そこが指す環境文書と端末別の記録を読む
3. ラッパーの有無を見る（`command -v` で PATH を確認する）
4. 実行先への疎通を確かめる

## ログ

SAS の成否はログの行頭で判定する。標準出力の見た目や終了コードで判断しない。

- `^ERROR` と `^WARNING` の件数を数える。行の途中に現れる ERROR という語は数えない
- ログはセッションの符号化で書かれる。読む側の符号化を合わせないと検出が効かない。shift-jis セッションのログを UTF-8 で読むと ERROR を取りこぼす
- WARNING は残ってよい。既知の WARNING と新しい WARNING を区別して報告する
- ログの本体はリポジトリの外に出る。git に入れない

同じ試験を複数の端末から同時に回さない。ログのファイル名は段と日付で決まり端末を区別しないため、後から書いたほうが前のを上書きする。

## 実行の前後

実行前にリポジトリを `git pull` する。生成物は git 管理外で、正本はリポジトリ側のスクリプトにある。古い版で回すと他の端末が入れた改善を黙って巻き戻す。

`.sas` は UTF-8（BOM なし）で保存する。

生データ・ログ・出力を git にコミットしない（`.sas7bdat`・`.xpt`・`.csv`・`.rtf`・`.xlsx` 等）。

## 報告

実行結果を報告するときは、段ごとの ERROR 件数・WARNING 件数・所要時間と、成果物の実体（パスとサイズ）を添える。「成功しました」だけで終えない。

ERROR が出たときは、ログの ERROR 行と、それがどのログファイルのものかを示す。
